# Multica 局域网接入说明（172.16.105.51）

本文说明如何从局域网内的电脑接入已部署在 `172.16.105.51` 上的 Multica，以及如何连接它的 PostgreSQL。

部署目录：`/home/multica`  
启动时必须同时带上官方编排和局域网覆盖文件，否则外网端口会丢：

```bash
cd /home/multica
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.lan.yml up -d
```

覆盖文件是 `/home/multica/docker-compose.selfhost.lan.yml`。端口只绑在 `172.16.105.51` 这块网卡上，不监听 `0.0.0.0`。

## 1. 地址一览

| 用途 | 地址 |
| --- | --- |
| 网页 | http://172.16.105.51:3000 |
| 后端 API | http://172.16.105.51:8080 |
| 健康检查 | http://172.16.105.51:8080/health |
| WebSocket | ws://172.16.105.51:8080/ws |
| PostgreSQL | `172.16.105.51:5432`，库名 `multica`，用户 `multica` |

从别的电脑访问时，不要把地址写成 `127.0.0.1` 或 `localhost`。那两个地址只在服务器本机有效。

当前实例允许注册（`ALLOW_SIGNUP=true`）。登录验证码不走邮件，使用服务器 `.env` 里的固定开发验证码。

## 2. 先确认网络

在要接入的电脑上执行。

Windows PowerShell：

```powershell
Test-NetConnection -ComputerName 172.16.105.51 -Port 3000
Test-NetConnection -ComputerName 172.16.105.51 -Port 8080
Test-NetConnection -ComputerName 172.16.105.51 -Port 5432
```

`TcpTestSucceeded` 为 `True` 才继续。网页和 API 也可以直接看返回：

```powershell
(Invoke-WebRequest -Uri http://172.16.105.51:8080/health -UseBasicParsing).Content
```

正常返回 JSON，其中 `"status":"ok"`。

Linux / macOS：

```bash
curl -sf http://172.16.105.51:8080/health
nc -vz 172.16.105.51 5432
```

端口不通时，先确认本机和 `172.16.105.51` 在同一可达网段，再在服务器上看监听：

```bash
ss -lntp | grep -E ':3000|:8080|:5432'
```

应看到 `172.16.105.51` 上的 `3000`、`8080`、`5432`。若 `5432` 消失，用第 8 节的命令把覆盖文件重新拉起来。

## 3. 网页接入

1. 浏览器打开 http://172.16.105.51:3000 。
2. 用邮箱注册或登录。
3. 验证码不在邮箱里。在服务器上读取固定码（6 位，不要把结果发到公共仓库）：

```bash
ssh root@172.16.105.51 "grep '^MULTICA_DEV_VERIFICATION_CODE=' /home/multica/.env"
```

4. 填入验证码，进入工作区。

这台服务器上的工作区、Issue、智能体、Skill 都在本机 PostgreSQL 里，和 Multica Cloud（`api.multica.ai`）不是同一份数据。

## 4. Desktop 接入

Desktop 和命令行各有一份配置，互不读取。Desktop 读的是用户主目录下的 `desktop.json`。

**重要：** 上游官网安装包默认连 Cloud。本仓库已把 Desktop 无 `desktop.json` 时的默认地址改为本机局域网：

- API：`http://172.16.105.51:8080`
- Web：`http://172.16.105.51:3000`
- WS：`ws://172.16.105.51:8080/ws`

用本仓库打出来的安装包，装完即可连 51，不必再写 `desktop.json`（仍可用该文件覆盖）。服务器上也留了模板与脚本：`/home/multica/public-client/desktop.json`、`setup-desktop-lan.ps1`（给旧官网包用）。

### 在本机构建 Windows Desktop（连 51）

需要 Node/pnpm、Go（打 CLI）、Windows 本机（打 `.exe`）：

```powershell
cd D:\qy566\aiworkspace\multica
pnpm install
pnpm --filter @multica/desktop exec electron-vite build --mode selfhost
$env:CSC_IDENTITY_AUTO_DISCOVERY = "false"
pnpm --filter @multica/desktop package -- --win --x64 --publish never
```

产物在 `apps/desktop/dist/`。把安装包放到 51 上分发即可。

Windows 路径：`C:\Users\<用户名>\.multica\desktop.json`
macOS / Linux 路径：`~/.multica/desktop.json`

文件内容：

```json
{
  "schemaVersion": 1,
  "apiUrl": "http://172.16.105.51:8080",
  "appUrl": "http://172.16.105.51:3000",
  "wsUrl": "ws://172.16.105.51:8080/ws"
}
```

Windows PowerShell 可直接写入：

```powershell
$dir = Join-Path $env:USERPROFILE ".multica"
New-Item -ItemType Directory -Force $dir | Out-Null
@'
{
  "schemaVersion": 1,
  "apiUrl": "http://172.16.105.51:8080",
  "appUrl": "http://172.16.105.51:3000",
  "wsUrl": "ws://172.16.105.51:8080/ws"
}
'@ | Set-Content -Encoding utf8 (Join-Path $dir "desktop.json")
```

然后完全退出 Multica Desktop 再打开。只关窗口不够，进程还在时不会重读这个文件。

登录用和第 3 节相同的邮箱与验证码。

恢复官方 Cloud：删除 `desktop.json` 后重启 Desktop。没有这个文件时，客户端默认连接 `https://api.multica.ai`。

## 5. 命令行与本机 Agent

`--server-url` 是后端，必须是 **8080**。`--app-url` 是网页，是 **3000**。两个都写成 3000 时，命令行会连到前端，健康检查失败。

Desktop 自带的命令行通常在：

```text
C:\Users\<用户名>\AppData\Local\Programs\@multicadesktop\resources\app.asar.unpacked\resources\bin\multica.exe
```

PowerShell：

```powershell
$multica = "$env:LOCALAPPDATA\Programs\@multicadesktop\resources\app.asar.unpacked\resources\bin\multica.exe"

& $multica setup self-host `
  --server-url http://172.16.105.51:8080 `
  --app-url http://172.16.105.51:3000
```

已有 Cloud 配置时，命令会询问是否覆盖。确认后按提示在浏览器登录。浏览器必须能打开 `http://172.16.105.51:3000`。

如果登录回调回不到这台电脑，加上本机局域网 IP（把地址换成运行命令的那台电脑，不是服务器）：

```powershell
& $multica setup self-host `
  --server-url http://172.16.105.51:8080 `
  --app-url http://172.16.105.51:3000 `
  --callback-host 172.16.105.x
```

想和 Cloud 配置并存时，使用独立 profile，避免写坏默认配置：

```powershell
& $multica setup self-host `
  --profile lan `
  --server-url http://172.16.105.51:8080 `
  --app-url http://172.16.105.51:3000
```

之后每条命令都加上 `--profile lan`。配置文件在 `%USERPROFILE%\.multica\profiles\lan\`。

检查是否指到这台服务器：

```powershell
& $multica config get
& $multica workspace list
```

`server_url` 应为 `http://172.16.105.51:8080`。

## 6. 数据库接入

应用容器走 Docker 内网主机名 `postgres`，不经过宿主机端口。下面的地址给服务器之外的客户端用，例如本机的 DBeaver、Navicat、脚本或其他服务。

### 6.1 连接参数

| 项 | 值 |
| --- | --- |
| 主机 | `172.16.105.51` |
| 端口 | `5432` |
| 数据库 | `multica` |
| 用户 | `multica` |
| 密码 | 服务器 `/home/multica/.env` 的 `POSTGRES_PASSWORD` |
| SSL | 关闭，`sslmode=disable` |
| 认证 | `scram-sha-256` |

密码长度 48，不是镜像默认的 `multica`。不要把密码写进仓库、聊天或截图。在服务器上查看：

```bash
ssh root@172.16.105.51 "grep '^POSTGRES_PASSWORD=' /home/multica/.env"
```

连接串（把 `<密码>` 换成上一行的值）：

```text
postgres://multica:<密码>@172.16.105.51:5432/multica?sslmode=disable
```

JDBC：

```text
jdbc:postgresql://172.16.105.51:5432/multica?sslmode=disable
```

这台库随 `pgvector/pgvector:pg17` 运行，PostgreSQL 17，带 pgvector。远程 `pg_hba.conf` 规则是 `host all all all scram-sha-256`，所以任何能到达 `172.16.105.51:5432` 的主机，只要密码正确就可以登录。

### 6.2 用 psql 验证

服务器上已有客户端时，在**接入电脑**执行：

```bash
psql "host=172.16.105.51 port=5432 user=multica dbname=multica sslmode=disable" -c "select current_user, current_database();"
```

提示输入密码。成功时两列都是 `multica`。

Windows 若已安装 PostgreSQL 客户端：

```powershell
$env:PGPASSWORD = "<密码>"
psql "host=172.16.105.51 port=5432 user=multica dbname=multica sslmode=disable" -c "select current_user, current_database();"
Remove-Item Env:PGPASSWORD
```

没有本机 `psql` 时，可以在服务器容器里绕到刚发布的地址，确认端口和认证一起是通的：

```bash
ssh root@172.16.105.51 'set -a; . /home/multica/.env; set +a; docker exec -e PGPASSWORD="$POSTGRES_PASSWORD" multica-postgres-1 psql -h 172.16.105.51 -p 5432 -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select current_user, current_database();"'
```

### 6.3 图形客户端（DBeaver、DataGrip、Navicat）

1. 新建 PostgreSQL 连接。
2. Host 填 `172.16.105.51`，Port 填 `5432`。
3. Database 填 `multica`，User 填 `multica`。
4. Password 填 `.env` 里的 `POSTGRES_PASSWORD`。
5. SSL 模式选 Disable。不要用 Require 或 Verify-Full，这条链路上没有配置证书，强制 SSL 会握手失败。
6. 测试连接。成功后再保存。

驱动需要支持 PostgreSQL 17 和 SCRAM-SHA-256。DBeaver、DataGrip 当前版本满足。过旧的 Navicat 或 JDBC 驱动会报 `password authentication failed` 或无法识别 SCRAM，把驱动升到支持 SCRAM 的版本。

### 6.4 程序里怎么写

Python（`psycopg` 3）：

```python
import os
import psycopg

conn = psycopg.connect(
    host="172.16.105.51",
    port=5432,
    dbname="multica",
    user="multica",
    password=os.environ["MULTICA_DB_PASSWORD"],
    sslmode="disable",
)
```

Go：

```go
dsn := "postgres://multica:" + url.QueryEscape(os.Getenv("MULTICA_DB_PASSWORD")) +
    "@172.16.105.51:5432/multica?sslmode=disable"
```

JDBC 属性：

```properties
jdbc.url=jdbc:postgresql://172.16.105.51:5432/multica
jdbc.username=multica
jdbc.password=${MULTICA_DB_PASSWORD}
sslmode=disable
```

密码放在接入方自己的环境变量或密钥管理里，不要写进源码。

### 6.5 不要改应用容器的库地址

`docker-compose.selfhost.yml` 里 backend 使用：

```text
postgres://multica:<密码>@postgres:5432/multica?sslmode=disable
```

这里的主机名 `postgres` 是容器网络内的服务名。把 backend 的 `DATABASE_URL` 改成 `172.16.105.51` 会让容器绕到宿主机，没有必要，重启时也更容易配错。外部工具才使用 `172.16.105.51:5432`。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 浏览器打不开 3000，健康检查也不通 | 本机到 `172.16.105.51` 的路由或交换机策略不通。先 `Test-NetConnection` 5432/8080/3000。 |
| 健康检查 404 | `--server-url` 指到了 3000。改成 `http://172.16.105.51:8080`。 |
| Desktop 仍进入 Cloud | `desktop.json` 不在用户主目录的 `.multica` 下，或 Desktop 没有完全退出。删掉错误文件，按第 4 节重写后从托盘退出再开。 |
| `desktop.json` 报 schema 错误 | `schemaVersion` 必须是数字 `1`。三个 URL 都要带协议，`wsUrl` 用 `ws://`，不要用 `http://`。 |
| 数据库超时 | 服务器上 `ss` 看不到 `172.16.105.51:5432`。按第 8 节重新挂上覆盖文件。 |
| `password authentication failed` | 密码不是 `multica`。重新从服务器 `.env` 复制 `POSTGRES_PASSWORD`，注意不要带上引号或换行。 |
| `no encryption` / SSL 握手失败 | 连接参数加上 `sslmode=disable`。 |
| `SCRAM` 相关认证错误 | 升级客户端或 JDBC 驱动。服务器只接受 SCRAM-SHA-256。 |
| 登录一直等邮件验证码 | 这台实例不发邮件。用 `.env` 里的 `MULTICA_DEV_VERIFICATION_CODE`。 |
| 看到的还是 Cloud 里的工作区 | Desktop 或 CLI 仍指向 `api.multica.ai`。Cloud 数据不会出现在这台库里。 |

## 8. 端口被重启弄丢时

只执行 `docker compose -f docker-compose.selfhost.yml up -d` 会回到仅容器内访问数据库、网页只绑 `127.0.0.1` 的状态。恢复局域网发布：

```bash
ssh root@172.16.105.51
cd /home/multica
docker compose -f docker-compose.selfhost.yml -f docker-compose.selfhost.lan.yml up -d
ss -lntp | grep -E ':3000|:8080|:5432'
curl -sf http://127.0.0.1:8080/health
```

`docker-compose.selfhost.lan.yml` 应包含：

```yaml
services:
  backend:
    ports:
      - "172.16.105.51:8080:8080"
  frontend:
    ports:
      - "172.16.105.51:3000:3000"
  postgres:
    ports:
      - "172.16.105.51:5432:5432"
```

数据在 Docker 卷 `pgdata` 里。重建 `multica-postgres-1` 容器不会清空数据；`docker compose down -v` 会删卷，不要加 `-v`。
